تعليمات لـ Replit Agent — تفعيل عزل Sandbox على Cloudflare (Dolphin)
====================================================================
انسخ هذا كامل والصقه في Replit Agent.

السياق: النظام يعمل كـ Cloudflare Worker (مشروع dolphin)، ويستخدم
Cloudflare Sandbox SDK (@cloudflare/sandbox) لتنفيذ كود مُجمَّع أو
مولَّد داخل حاويات معزولة قبل قبوله كعينة تدريب. المطلوب الآن
تفعيل إعدادات الأمان المؤكدة رسمياً من توثيق Cloudflare، وإضافة
حماية مسؤوليتنا نحن (مو مسؤولية المنصة).

--------------------------------------------------------------------
1) تعطيل الشبكة بالكامل داخل الـ sandbox
--------------------------------------------------------------------
عند بدء أي sandbox لتنفيذ كود غير موثوق، مرّر enableInternet: false
صراحة. هذا يمنع أي اتصال شبكي داخل أو خارج الحاوية بشكل كامل
(all-or-nothing، لا استثناءات جزئية).

مثال:
```ts
const sandbox = getSandbox(env.Sandbox, sandboxId);
await sandbox.start({ enableInternet: false });
```

تأكيد مطلوب: اطبع/سجّل قيمة enableInternet الفعلية المطبَّقة في
اللوق عند كل بدء تشغيل sandbox، حتى يكون هناك دليل تشغيلي أن
الإعداد فعلاً يُمرَّر ولا يسقط بصمت بسبب خطأ في الإعداد الافتراضي.

--------------------------------------------------------------------
2) حدود الموارد (CPU / ذاكرة)
--------------------------------------------------------------------
اضبط حدود الموارد على مستوى إعداد الـ Container نفسه (خارج كود
التشغيل، في تعريف الحاوية) بما يعادل ما اعتمدناه سابقاً:
- ذاكرة: 256 MiB كحد أقصى لكل sandbox.
- CPU: ما يعادل 0.5 vCPU.

إن كانت منصة Cloudflay Containers تفرض حدوداً افتراضية مختلفة عن
هذي القيم بحكم خطة الحساب، اذكر القيم الفعلية المطبَّقة فعلياً —
لا تفترض أنها 256 MiB / 0.5 vCPU إذا لم يكن هذا مضبوطاً صراحة.

--------------------------------------------------------------------
3) مهلة زمنية صارمة (Timeout)
--------------------------------------------------------------------
اضبط مهلة تنفيذ لكل أمر داخل الـ sandbox بحد أقصى 10 ثوانٍ
wall-clock، بحيث يُقتل التنفيذ تلقائياً عند تجاوزها بدون grace
period. استخدم containerTimeouts أو ما يعادلها في SDK الحالي،
واذكر اسم الإعداد الفعلي المستخدم.

--------------------------------------------------------------------
4) تعقيم كل مدخل يمرّ لـ sandbox.exec() — مسؤوليتنا نحن، لا المنصة
--------------------------------------------------------------------
توثيق Cloudflare يوضح صراحة أن التحقق من صحة المدخلات ومنع
الثغرات على مستوى التطبيق مسؤولية المطوّر، لا الحاوية. لذلك:

- قبل تمرير أي نص لـ sandbox.exec(command)، طبّق فلترة صارمة:
  ارفض أي حرف خارج المجموعة المسموحة (أحرف/أرقام/نقطة/شرطة سفلية/
  شرطة عادية/مسافة)، وارفض التنفيذ كاملاً إذا وُجد حرف مرفوض بدل
  محاولة "تنظيفه" جزئياً.

مثال:
```ts
function sanitizeForExec(input: string): string | null {
  const allowed = /^[a-zA-Z0-9._\-\s]+$/;
  if (!allowed.test(input)) return null; // رفض كامل، لا تعديل جزئي
  return input;
}
```

- لا تبني أي أمر عبر تجميع نص (string concatenation) مباشرة من
  مدخلات غير موثوقة (اسم ملف من الويب، محتوى مكشوط، إلخ) — مرّرها
  دائماً كـ argument منفصل، لا كجزء من سلسلة الأمر.

--------------------------------------------------------------------
5) عزل sandbox واحد لكل مهمة/مصدر
--------------------------------------------------------------------
لا تُعِد استخدام نفس معرّف sandbox (sandboxId) لمصادر أو مهام
مختلفة — كل sandbox يشارك الملفات والعمليات داخلياً بين كل ما
يُشغَّل فيه. استخدم معرّفاً فريداً لكل مهمة تنفيذ (مثلاً
`task-${taskId}`)، لا معرّفاً ثابتاً عاماً.

--------------------------------------------------------------------
6) نتيجة التنفيذ والقرار
--------------------------------------------------------------------
عند انتهاء التنفيذ:
- exit code = 0 وقبل انتهاء المهلة → passed.
- أي شيء آخر (فشل، timeout، رفض من sanitizeForExec) → rejected،
  مع تسجيل السبب الحقيقي في جدول العينات (لا تخمين نتيجة، تطابقاً
  مع البند 5 من دستور النظام: لا ادّعاء نجاح لم يتحقق منه فعلياً).
- حتى بعد passed، العينة تبقى pending_human_review ولا تدخل
  التدريب قبل موافقة بشرية.

--------------------------------------------------------------------
مطلوب منك تحديداً (لا تنفّذ بصمت، أجب بالتفصيل)
--------------------------------------------------------------------
1. أكّد القيم الفعلية المطبَّقة لكل بند أعلاه (لا "تم بنجاح" فقط).
2. إن كان أي بند غير مدعوم فعلياً بصيغته الحالية على SDK/الخطة
   المستخدمة، اذكر ذلك صراحة والبديل الأقرب المتاح.
3. لا تفعّل أي وظيفة تسمح بشبكة جزئية أو allowlist نطاقات داخل نفس
   sandbox التنفيذ — إن احتجت وصول شبكي لاحقاً (رفع لـ Hugging
   Face مثلاً)، يكون من Worker/Queue منفصل تماماً، لا من هذا
   الـ sandbox.
